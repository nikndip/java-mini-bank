# Работа с моделью и проверка результата

Это итоговый проект по промпт-инжинирингу для разработчиков. Использование языковой модели предусмотрено заданием; предмет работы — не только программа, но и сохранённый управляемый процесс её получения и проверки. Для рабочих запросов использовалась `gpt-6.1-sol` с уровнем reasoning `high` в Codex.

Полные тексты запросов, ответы, версии материалов, протоколы запусков и журнал находятся в [учебном архиве](../mini-bank-project.zip). Краткое изложение и ссылки на свидетельства включены в [отчёт](../mini-bank-report.pdf). Эти два файла зафиксированы при завершении учебного этапа. README, скрипт проверки и workflow добавлены позднее для публикации в портфолио.

## Последовательность

| Шаг | Результат | Основание для продолжения |
|---|---|---|
| A. Аудит требований и карты в отдельном чате | Замечания к входам, выходам, переходам и ограничениям | Разбор замечаний и принятие карты |
| B. Подготовка сценариев | Входы, точные ожидаемые ответы и связи с R01–R12 | Проверка покрытия и граничных случаев |
| C. Реализация | Java-код по принятому контракту | Фактическая компиляция и запуски |
| D. Разбор результатов | Сопоставление ожиданий и факта, область проверенного | Решение о приёмке либо локальном возврате |
| E. Условное исправление | Локальная правка одного дефекта | Повтор сбойного сценария и связанных проверок |
| F. Итоговая приёмка | Матрица требований, акт, отчёт и архив | Полный прогон принятого набора и решение автора |

Ответ модели о работоспособности не заменял запуск. Ожидания определялись из требований до выполнения программы. В журнале различаются запросы модели, проверки инструментами и решения автора.

## Учебный сбой D01

Первый вариант программы прошёл подготовленные сценарии. Для обязательного разбора восстановления была сделана отдельная копия, в которой намеренно заменили `amount > LIMIT` на `amount >= LIMIT`. Это учебный дефект, а не ошибка, приписанная модели.

Сценарий T05 выявил отклонение: вместо `OK DEPOSIT A 1000000000` программа напечатала `ERR_AMOUNT`. При этом процесс завершился с кодом 0. Проверяющая программа обнаружила несовпадение stdout и завершилась с кодом 1. Этот случай показывает, почему успешного завершения процесса недостаточно для приёмки поведения.

На исправление был отправлен один запрос. После возврата строгого сравнения `>` исправленная копия побайтно совпала с рабочим исходником. Повторно выполнены T04, T05, T07, T12 и T13, затем весь итоговый набор: 14 различных сценариев, 17 запусков, без несовпадений.

При независимой проверке уточнили и описание области влияния: T07 проверяет достижение лимита **баланса получателя** небольшими суммами операций. Он входил в повторную проверку; его падение на испорченной версии не было подтверждено запуском. Исходное свидетельство сбоя T05 и исправление описания сохранены в архиве.

## Воспроизводимость

Итоговый набор включает пять граничных сценариев: T04–T07 и T12. Сохраняются точные входы, ожидаемый и фактический вывод, версии Java, команды и SHA-256 проверенных файлов. Повтор одного сценария не считается новым различным сценарием.

При проверке инструкции обнаружилась отдельная проблема PowerShell: аргумент `-Dfile.encoding=UTF-8` нужно передавать в кавычках. После исправления команды запуск из чистой копии прошёл успешно. В текущем README и скрипте используется корректная форма `"-Dfile.encoding=UTF-8"`.
