# Устройство Mini Bank

Программа намеренно помещается в один класс: учебное задание ограничивает основной код 50–150 непустыми строками без строк только с комментариями. В `src/MiniBank.java` — 106 таких строк. Проверяющая программа находится отдельно, в `tests/MiniBankChecks.java`.

## Обработка команды

```text
stdin → разбор команды и аргументов → проверки → изменение состояния → stdout
                                          ↘ отказ: состояние сохраняется
```

`main` читает UTF-8 построчно. Команды разбиваются по пробелам и табуляциям; сначала проверяются название и количество аргументов, затем существование счетов. `accountIndex` сопоставляет `A` и `B` индексам массива балансов. `parseAmount` проверяет сумму посимвольно: допускает только цифры ASCII и значение от 1 до 1 000 000 000. Начальные нули допустимы, в том числе длинная последовательность перед значимой цифрой.

Порядок проверок зафиксирован в R11: команда, счёт, сумма, перевод себе, наличие средств, лимит баланса. После первого нарушения выводится один код ошибки. Успешные проверки предшествуют изменению обоих балансов и добавлению записи в историю. Поэтому отказ не оставляет частично выполненный перевод.

## Деньги и состояние

Балансы хранятся в `long[2]` в целых копейках. Дробная арифметика и округление не используются. При проверке лимита сравниваются текущий баланс и `LIMIT - amount`, после чего выполняется сложение. Общая история — `ArrayList<String>` с успешными операциями в исходном порядке.

Данные принадлежат одному процессу. При следующем запуске создаются новые нулевые балансы и пустая история. Программа однопоточная; хранение на диске, конкурентные операции, авторизация и сетевой доступ не входят в контракт.

## Проверки

`MiniBankChecks` читает входы и ожидаемые ответы из `tests/scenarios-v2.md`, компилируется отдельно и запускает приложение в дочерних JVM. Сравнение учитывает весь stdout, включая порядок сообщений и завершающие переводы строк; CRLF приводится к LF. stderr должен быть пустым. Код завершения процесса сохраняется как свидетельство, но сам по себе не доказывает правильность ответа.

`scripts/verify.ps1` выбирает JDK из `JAVA_HOME` или `PATH`, требует Java 17, компилирует оба файла и выполняет 17 запусков для 14 сценариев. Для каждого выполнения создаётся новая папка результатов в `build/`. GitHub Actions вызывает тот же скрипт на Ubuntu и Windows при push, pull request или ручном запуске. Удалённый результат подтверждается конкретным запуском Actions после публикации.
