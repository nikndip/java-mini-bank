# Mini Bank

![Java 17](https://img.shields.io/badge/Java-17-007396) ![Standard library](https://img.shields.io/badge/dependencies-standard_library-555555)

Учебное CLI-приложение на Java 17: пополнение двух счетов, переводы, баланс и история операций. Проект выполнен с предусмотренным заданием использованием LLM и управляемым процессом разработки: требования, проверочные сценарии, реализация и разбор результатов.

Ценность работы — проверяемые требования, 14 сценариев с 17 отдельными запусками, 5 граничных сценариев и разбор учебного сбоя. Роль модели и решения автора описаны в [процессе работы с LLM](docs/llm-workflow.md).

## Возможности и границы

| Команда | Действие |
|---|---|
| `balance A` | Показать баланс выбранного счёта |
| `deposit A 1000` | Пополнить счёт на 1000 копеек |
| `transfer A B 250` | Перевести 250 копеек между счетами |
| `history` | Показать успешные пополнения и переводы по порядку |
| `exit` | Вывести `BYE` и завершить программу |

Существуют только вымышленные счета `A` и `B`. Каждый запуск начинается с нулевых балансов и пустой истории; данные остаются в памяти процесса. Суммы хранятся как `long` в целых копейках: сумма операции — от 1 до 1 000 000 000, баланс — от 0 до 1 000 000 000 включительно. Ввод суммы допускает только цифры ASCII, включая начальные нули.

Ошибочная операция сохраняет оба баланса и историю. Команды чувствительны к регистру; пробелы и табуляции между аргументами допустимы. Программа читает stdin до `exit` или конца потока, без меню и приглашений. Регистрация, авторизация, постоянное хранение, кредиты и реальные банковские операции выходят за рамки задания.

## Запуск

Нужен JDK 17 с `javac` и `java` в `PATH`. Maven и сторонние библиотеки не требуются. Все команды выполняются из корня проекта.

Сборка и интерактивный запуск одинаковы в Windows PowerShell и bash:

```sh
javac --release 17 -encoding UTF-8 -d build/classes src/MiniBank.java
java "-Dfile.encoding=UTF-8" -cp build/classes MiniBank
```

Короткий пример ввода из [tests/demo-input.txt](tests/demo-input.txt):

```text
balance A
deposit A 1000
transfer A B 250
history
exit
```

Вывод, зафиксированный в [tests/demo-expected.txt](tests/demo-expected.txt):

```text
BALANCE A 0
OK DEPOSIT A 1000
OK TRANSFER A B 250
DEPOSIT A 1000
TRANSFER A B 250
BYE
```

Запуск этого примера в PowerShell:

```powershell
Get-Content -Encoding UTF8 tests/demo-input.txt | java "-Dfile.encoding=UTF-8" -cp build/classes MiniBank
```

В bash:

```bash
java -Dfile.encoding=UTF-8 -cp build/classes MiniBank < tests/demo-input.txt
```

## Проверки

В Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1
```

Скрипт компилирует приложение и проверочный код в `build/classes` и `build/checks`, выполняет принятый набор [tests/scenarios-v2.md](tests/scenarios-v2.md) и сохраняет результаты в новую папку `build/results-<id>`.

Без PowerShell достаточно трёх переносимых команд `javac`/`java`. Для каждого запуска заменяйте `build/results-manual-001` новым, ещё не существующим путём: проверяющая программа отклоняет существующую папку.

```sh
javac --release 17 -encoding UTF-8 -d build/classes src/MiniBank.java
javac --release 17 -encoding UTF-8 -d build/checks tests/MiniBankChecks.java
java "-Dfile.encoding=UTF-8" -cp build/checks MiniBankChecks build/classes build/results-manual-001 tests/scenarios-v2.md src/MiniBank.java
```

Проверяющая программа запускает отдельный процесс на каждый из 17 запусков, сравнивает stdout с ожидаемым текстом и требует пустой stderr. CRLF нормализуется в LF; остальные символы и завершающие переводы строк учитываются. В папке результатов сохраняются вход, ожидаемый и фактический вывод, код процесса, команды, SHA-256 исходника и набора сценариев, а также сводка `results.md`.

Набор охватывает начальное состояние, сброс данных между процессами, операции в обоих направлениях, ошибочный ввод, приоритет ошибок, неизменность состояния при отказах и завершение. Пять граничных сценариев: T04 — сумма 1 и баланс 0; T05 — сумма и баланс 1 000 000 000; T06 — нехватка одной копейки; T07 — предел баланса получателя; T12 — формат и границы суммы, длинные начальные нули. Это проверка заданного контракта в пределах принятого набора сценариев.

Workflow [ci.yml](.github/workflows/ci.yml) предназначен для запуска проверок на Java 17 в Ubuntu и Windows. Результат удалённого CI определяется конкретным запуском GitHub Actions.

## Устройство и решения

- Один класс приложения и стандартная библиотека соответствуют небольшому объёму задания; проверочный код хранится отдельно.
- Целые копейки исключают округление при операциях. Посимвольный разбор суммы проверяет ASCII-цифры и ограничение до изменения состояния.
- Проверки выполняются в заданном порядке: команда → счёт → сумма → перевод себе → средства → лимит. Балансы и история меняются только после успешной проверки.
- В историю попадают только успешные операции. UTF-8 и фиксированный текстовый протокол позволяют воспроизводимо сравнивать результаты.

## Структура и учебные материалы

```text
src/MiniBank.java          приложение
tests/MiniBankChecks.java  проверяющая программа
tests/scenarios-v2.md      принятый набор сценариев
tests/demo-*.txt           пример ввода и ожидаемого вывода
scripts/verify.ps1         локальная проверка

docs/                     требования, архитектура, работа с LLM
mini-bank-report.pdf      учебный отчёт
mini-bank-project.zip     полный учебный комплект
```

[Отчёт PDF](mini-bank-report.pdf) и [архив проекта ZIP](mini-bank-project.zip) включены как зафиксированные учебные материалы. Архив сохраняет полный комплект, включая исходные запросы к модели, протоколы и предыдущие версии документов. Публичное дерево содержит компактный набор для знакомства с проектом и повторного запуска проверок.
