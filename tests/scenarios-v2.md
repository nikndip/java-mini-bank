## Общие правила запуска и сравнения

Используется Java 17. Вход и выход сохраняются в UTF-8.

Каждый сценарий выполняется независимо. Каждый обозначенный запуск использует новый процесс одной и той же проверяемой версии программы. Предусловия состояния задаются командами непосредственно в stdin этого запуска.

После подготовки и сборки реализации действие «запуск программы» означает:

```text
java -Dfile.encoding=UTF-8 -cp src MiniBank
```

Каждая непустая строка stdin завершается переводом строки. После последней строки входной поток закрывается. Пустой блок stdin означает немедленный конец потока. Блок с одной пустой строкой означает ввод пустой строки с последующим концом потока. Табуляции внутри блоков представлены настоящими символами TAB.

Предусмотренные ответы приведены в stdout согласно формату задания шага B. Ожидаемый stderr каждого запуска пуст — 0 байт. Меню, приглашений, отладочного текста и дополнительных строк в stdout не ожидается.

Каждая строка ожидаемого сообщения завершается переводом строки. Требование R12 не устанавливает выбор между LF и CRLF; представление строк в документе не вводит такого ограничения.

Числовой код завершения не нормируется R01–R12. При выполнении сценария сохраняется фактический код; условие равенства конкретному числу не добавляется. Завершение процесса по `exit` или концу потока и соответствие вывода проверяются по R12.

Статус всех сценариев и проверок: **не проверено**. Фактические stdout, stderr, коды завершения и подтверждения запуска отсутствуют.

Проверяемые сочетания в порядке входных команд:

1. `transfer C C 0 extra`: неверная арность, счета и сумма → `ERR_COMMAND`.

3. `transfer C A 0`: неверный отправитель и сумма → `ERR_ACCOUNT`.
4. `transfer A A 0`: неверная сумма и перевод себе → `ERR_AMOUNT`.
5. `transfer A A 700000000`: перевод себе; сумма превышает средства A, а её прибавление к исходному балансу A превысило бы лимит → `ERR_SAME_ACCOUNT`.
6. `transfer A B 700000000`: недостаток средств A и превышение лимита B → `ERR_FUNDS`.
7. `transfer B A 500000000`: средств B достаточно, но новый баланс A составил бы 1100000000 → `ERR_LIMIT`.
8. `deposit B 1000000001`: недопустимая сумма и потенциальное превышение балансового лимита → `ERR_AMOUNT`.

### T14 Завершение по exit и игнорирование следующих строк

### V04 Объём исходного кода и отделение проверочного кода

- Правила подсчёта:
  - учитывать все исходники, входящие в программу, включая вспомогательные файлы, если они появятся;
  - не включать отдельно хранящийся проверочный код;

## Уточнения при проверке сценариев

U01. Исходный ответ модели обозначил как Q01 вопрос о числовом коде
завершения. Здесь используется ID U01, чтобы отличать вопрос
от номера фактически отправленного запроса Q01 в журнале.
При сверке установлено: требования задают завершение процесса,
но не конкретное числовое значение его кода. Поэтому версия 2
предусматривает запись фактического кода без нового числового условия.
Коды сообщений ERR_COMMAND и других ошибок в stdout остаются
обязательными по требованиям и проверяются точно.

Уточнение проверки V04 из исходного условия задания.
При подсчёте строк дополнительно проверить, что операторы не объединены
ради уменьшения объёма и лишний код не добавлен ради достижения 50 строк.
Правило подсчёта физических строк само по себе не разрешает уплотнять код.
